# NEUROGENESIS — экспериментальное локальное LLM-ядро

Это изолированный прототип локальной генерации. Он **не подключён к основному чату** и не меняет существующую память.

## Состав

- `local-llm-worker.js` — загрузка модели и генерация в Web Worker.
- `local-llm-adapter.js` — адаптер формата `NGLLMBridge` (`generate` / `generateDetailed`).
- `dev/local-llm-test.html` — отдельная страница для ручной проверки.
- `tests/local-llm.test.js` — офлайн-тесты с фиктивным runtime и Cache API.

## Зафиксированные ресурсы

- Модель: [`onnx-community/Qwen3-0.6B-ONNX`](https://huggingface.co/onnx-community/Qwen3-0.6B-ONNX)
- Ревизия модели: `a7b503b1c3f7e98e8f80b6d565f47807a5007d9c`
- Runtime: [`@huggingface/transformers` 4.3.2](https://github.com/huggingface/transformers.js/releases/tag/4.3.2)
- Основной файл WebGPU `onnx/model_q4f16.onnx`: примерно 570 MB.
- Резервный файл WASM `onnx/model_q4.onnx`: примерно 919 MB.
- SHA-256 файла `model_q4f16.onnx` по метаданным Hugging Face: `9e33a5911974174761d0dfdcc0bec975d9c45af0eae5e9eb647b8ba9442a8f91`.

Веса не включаются в Git. Worker выбирает только нужный вариант весов и необходимые конфигурационные файлы.

## Ручной запуск

Из распакованной папки прототипа запусти локальный HTTP-сервер в Termux (Node.js 22+):

```bash
node dev/serve-local.mjs
```

Открой в Chrome на этом же телефоне:

`http://127.0.0.1:8765/dev/local-llm-test.html`

Сервер обслуживает только текущую папку и слушает localhost. Альтернатива на компьютере — `python3 -m http.server 8000`.

Нажми «Загрузить модель». Первая загрузка требует интернета и может скачать сотни мегабайт. После загрузки отправь тестовый вопрос на русском.

Для проверки повторного запуска перезагрузи страницу и нажми «Проверить кэш» или загрузи модель повторно.

## Диагностика WebGPU и распределения операций

Изолированная тестовая страница также собирает диагностические данные после загрузки модели:

- версию Transformers.js и встроенную версию ONNX Runtime Web;
- доступные WebGPU-функции, сведения об адаптере и его лимиты (часть сведений браузер может скрыть);
- WASM-настройки, если они доступны;
- предупреждения ONNX Runtime о назначении узлов execution provider во время создания сессии;
- длительность отдельных GPU-ядер, если адаптер поддерживает `timestamp-query` или экспериментальный вариант timestamp queries.

Для профилирования используется `env.backends.onnx.webgpu.profiling.mode = "default"` и callback `ondata`, доступные в используемом ONNX Runtime Web 1.31.0-dev. При создании сессии временно включается подробный лог ONNX Runtime; после загрузки исходный уровень логирования восстанавливается.

**Как читать результаты:** сумма времени GPU-ядер не равна полному времени ответа и не является процентом нагрузки GPU. Если timestamps не поддерживаются, блок покажет, что GPU-профиль недоступен. Предупреждение о не назначенных узлах само по себе не доказывает CPU fallback: некоторые служебные операции штатно выполняются на CPU. Диагностика даёт наблюдаемые факты для следующего шага, но не обещает автоматически ускорить генерацию.

## Ограничения, которые пока не закрыты

1. Реальные веса не запускались в CI и не проверялись на Android.
2. WebGPU, WASM fallback, время генерации и качество русского ответа требуют ручного прогона на целевом телефоне.
3. Кэш проверяется по размерам файлов. Worker пока не вычисляет SHA-256 содержимого 570-мегабайтного файла.
4. Метаданные модели сохраняются в Cache API. Реальная гарантия офлайн-запуска не установлена.
5. Transformers.js загружается с jsDelivr. Если браузер не сохранил ESM-модули runtime и нужные WASM-файлы, после отключения сети старт может не состояться. Полный автономный запуск после первой загрузки ещё не подтверждён.
6. Запрос `navigator.storage.persist()` — просьба браузеру, а не гарантия бессрочного хранения.

## Проверка

Команда:

```bash
node tests/local-llm.test.js
```

Офлайн-тесты используют поддельный runtime и не скачивают веса. Их успешное прохождение подтверждает протокол Worker/адаптера и обработку тестовых состояний, но **не подтверждает фактическую генерацию Qwen3**.

Синтаксис:

```bash
node --check local-llm-worker.js
node --check local-llm-adapter.js
```

## Подключение к основному чату

Пока не выполняется автоматически. Для будущей интеграции:
- загрузить `local-llm-adapter.js` после `llm-bridge.js`, но до `memory.js`;
- создать адаптер через `NGLocalLLM.create(...)`;
- явно загрузить модель по действию пользователя;
- зарегистрировать адаптер через `registerWith(NGLLM)`;
- учитывать, что `NGLLMBridge.create().register()` автоматически активирует только первый зарегистрированный провайдер. Если уже выбран `worker-proxy`, для переключения нужен явный `NGLLM.select("local")`;
- изменить `askWithLLM` так, чтобы он мог использовать локальный провайдер даже при отсутствии `llmHttpAdapter`.

Основные файлы приложения намеренно не изменены в этом этапе.
